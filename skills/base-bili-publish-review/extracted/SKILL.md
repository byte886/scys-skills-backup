# base-bili-publish-review

## 适用场景

当用户准备发布 B站数码家电带货视频，或者视频发布后需要做一次简单复盘时，使用本 skill。

这个 base_skill 的教学目标是：让学习者理解发布不是终点，工作流需要有发布前检查和发布后反馈。

## 需要输入

发布前至少提供：

- 标题
- 封面文案或封面图说明
- 口播稿
- 商品顺序
- 商品卡或链接顺序

发布后可以补充：

- 播放量
- 完播率或平均观看时长
- 点击率
- 评论反馈
- 用户提问

## 执行步骤

1. 发布前检查标题、封面、脚本和商品顺序是否一致。
2. 检查标题和封面是否存在过度承诺。
3. 检查简介或评论区引导是否清楚。
4. 发布后把数据和评论拆成表现、问题和下一步动作。
5. 给出下一条视频的优化建议。

## 输出格式

```markdown
## 发布前检查

| 检查项 | 结果 | 问题 | 建议 |
|---|---|---|---|
| 标题与内容一致 | 通过 | 无 | 保持 |

## 发布结论

结论：可以发布 / 修改后发布 / 暂缓发布
原因：...

## 发布后复盘

| 指标或反馈 | 观察 | 可能原因 | 下一步动作 |
|---|---|---|---|
| 评论集中问价格 | 用户仍有决策疑问 | 价格展示不够清楚 | 下一条加强价格对比 |
```

## 质量检查标准

- 标题、封面、脚本和商品顺序必须一致。
- 不能把数据不足解读成确定结论。
- 复盘建议要能转成下一条视频的具体动作。
- 发现严重不一致时，必须建议暂缓发布或修改后发布。
- 输出要同时覆盖发布前检查和发布后复盘，除非用户明确只做其中一项。

## 简单示例

输入：

```text
标题：租房厨房必买 3 件电器。封面写“闭眼买”。脚本里说每个人需求不同，要按空间和预算选。
```

输出要点：

- 标记封面“闭眼买”与脚本的保守建议不一致。
- 建议改成“租房厨房 3 件电器怎么选”。
- 发布结论为修改后发布。
