# 诊断矩阵（MVP）

| 表面症状 | 首先核查 | 常见根因假设 | 首个验证动作 |
|---|---|---|---|
| 没有曝光 | 渠道、平台、内容频率 | 人群与平台不匹配，或内容没有明确需求 | 选一个明确人群和一个高频问题，连续测试一组内容 |
| 有曝光无关注 | 点击/访问与关注比 | 承诺不一致、定位不清、缺少信任或行动指令 | 重写一个入口页面/简介，并比较访问到关注的变化 |
| 有关注无咨询 | 进入留量池和咨询路径 | 没有进入理由、承接断裂、内容与产品脱节 | 设计一个低门槛承接物，观察进入率与有效咨询率 |
| 留量池不活跃 | 首次价值、活跃、复访 | 用户没有获得持续价值，或运营节奏不稳定 | 为新用户设计一次明确的首次价值体验 |
| 活跃不成交 | 需求、产品、信任、价格 | 用户兴趣存在但购买理由不足 | 针对一个细分需求做一轮小范围转化实验 |
| 成交不复购 | 交付、持续价值、复购触发 | 交付结束即关系结束，缺少下一步价值 | 设计交付后的回访与下一产品承接 |

这张表只用于首轮路由，不替代证据。每次诊断必须结合用户具体数据修正。

## 优先级规则

当多个环节同时异常时，优先处理离收入最近、且能在一人资源约束下被单变量验证的环节：

1. 已有有效用户但不成交/不复购；
2. 已有关注或进入留量池但没有完成关键行为；
3. 有曝光但不精准或不承接；
4. 完全没有有效曝光。

这不是绝对排序。如果上游流量几乎为零，或产品/人群尚未定义，必须先收集信息并标记低置信度，而不是强行诊断下游转化。
