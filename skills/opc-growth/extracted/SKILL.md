# OPC-Growth

## 目标

把“没有流量”拆成可验证的问题：目标用户是否出现、是否精准、是否愿意停留、是否进入可持续触达的留量池、是否获得价值、是否成交和复购。优先找出当前最限制业务的一个瓶颈，不一次性给出十个泛化建议。

## 核心原则

- 流量不等于增长；先区分曝光、有效访问、留量、成交和复购。
- 留量必须同时包含可持续触达、用户关系、价值服务和可复用机制，不能把“加了联系方式”自动视为留量池。
- 先查漏斗位置，再查根因；没有数据时用用户能理解的自然语言说明“这是暂定判断”，不伪装成结论。
- 一人公司的方案必须考虑时间、预算、个人能力和交付能力，优先选择一个人能在 7-14 天内完成的验证动作。
- 保留来源依据与推理链：书中原则、用户提供的数据、诊断推断、待验证假设要分开表达。

## 触发边界

只有当用户同时提供了（或明确想解决）一个具体经营症状，例如“有曝光无咨询”“社群不活跃”“成交后没有复购”“冷启动没有有效用户”，才进入诊断流程。

以下请求不要调用本 Skill 的完整诊断流程：单纯写一篇文案、直接比较平台排名、要求一套泛化的全渠道营销计划、安排日程，或只询问“什么是流量/留量”。简短说明本 Skill 需要具体经营症状，再邀请用户补充业务、人群、平台和结果数据。

如果用户的问题同时包含平台选择和具体症状，只诊断症状；平台只是待验证变量，不直接给平台总排名。

## 工作流程

### 0. 先用用户听得懂的话说

- 先给一句日常语言的暂定结论，再解释依据；第一次出现“漏斗”时说成“从看到内容、关注、加微信、咨询到成交的路径”。
- 不向用户展示“低置信度”“证据等级”等内部评估术语；使用“先给你一个暂定判断：还缺少……，所以现在不能把根因说死”。
- 不把“单变量实验”原词当作必要术语；改说“这 7-14 天只改一件事”。
- 用户追问“还有什么建议”时，保留当前唯一优先动作；其他建议标为“后续再做”，不能让用户误以为需要同时执行。

### 首轮轻问询规则

当用户只说了一个经营症状、但还没有提供业务和结果数据时，首轮只做信息收集，不进入诊断：

- 不输出暂定结论、证据分析、优先动作、7-14 天实验或一长串建议。
- 只用一句话承接：“好，我先问你 3 个问题，了解情况后再判断。”
- 首轮最多问 3 个问题，合并询问：卖什么/服务谁/想要什么结果；主要在哪里获客；最近 7-30 天大概有多少曝光、关注/加微信、咨询和成交。不知道的数字可以写“不知道”。
- 用户回答后，只追问仍然缺失且会影响判断的信息，最多再问 2 个问题；不要把 6 个问题一次性全部列出。
- 只有收集到足以判断主要环节的信息后，才使用正式诊断结构。

### 1. 判断诊断场景

把用户问题归入一个主场景：

- 冷启动：刚开始做业务，曝光和有效用户都不足；
- 流量停滞：曾经有流量或增长，后来下降或无法复制；
- 有曝光无转化：有阅读、播放或点赞，但没有关注、咨询或成交；
- 有用户不留存：用户进入后不活跃、不复访或无法持续触达；
- 有成交无复购：首次交易存在，但持续价值和用户复用不足。

若多个场景同时存在，先选离收入最近且最可能限制增长的一个，不默认从“增加曝光”开始。

### 2. 收集最低必要信息

进入正式诊断后，优先询问最近 7-30 天的数据；没有数据时接受定性回答，但要用自然语言说明判断是否暂定，不要直接展示“低置信度”等内部评估术语：

1. 业务卖什么、服务谁、当前最想达成的结果；
2. 主要平台和内容/获客方式；
3. 最近发布或获客频率；
4. 曝光、点击/访问、关注/加联系方式、咨询、成交、复购中已知的数字；
5. 用户进入后被引导到哪里，首次获得的价值是什么；
6. 一个人每周能投入多少时间和预算。

如果进入正式诊断后仍缺少产品/用户/平台/结果中的两个或以上关键字段，继续用自然语言说明“还缺少……，所以现在不能把根因说死”；不要直接给出确定的根因、精确目标或复杂方案。

### 3. 定位漏斗环节

按以下顺序检查，不跨级开药：

1. 没有曝光：检查渠道、平台匹配、内容供给和发布机制；
2. 有曝光但不精准：检查目标人群、选题、关键词和平台用户关系；
3. 有点击但不关注：检查内容承诺、账号定位、信任证明和下一步指令；
4. 有关注但不进入留量池：检查承接入口、进入理由、利益承诺和触达机制；
5. 进入留量池但不活跃：检查首次价值、内容/服务产品化、运营频率和召回；
6. 活跃但不成交：检查需求匹配、产品价值、信任、价格、场景和转化设计；
7. 成交但不复购/转介绍：检查交付体验、持续价值、用户分层和复购机制。

如果用户同时使用广告、内容、转介绍等多个获客方式，却没有记录来源，且问题是“新流量不稳定”，优先做来源归因；在知道哪个来源带来有效咨询或成交前，不建议增加预算或同时扩大多个渠道。

### 4. 输出诊断

每次诊断只能选一个主瓶颈。其他问题只能作为暂不优先项或后续分支，不得并列输出多个“最重要的问题”。

固定使用以下结构：

```text
一句话结论：当前最可能的主瓶颈是……
证据：用户提供的事实……
推理：这些事实说明漏斗中的……比……更值得优先处理。
暂不优先：……，因为……
优先动作：只做一个动作……
7-14 天实验：对象、动作、频率、负责人、时间盒。
观察指标：主指标……；辅助指标……；停止/调整条件……
下一分支：若主指标改善，进入……；若无改善，检查……
判断状态：暂定/较明确/明确；还缺少……（用自然语言解释，不使用“低置信度”等内部术语）
```

其中“7-14 天实验”必须明确：目标用户、只改变的一个变量、具体动作与频率、主指标、辅助指标、成功条件和停止/调整条件。没有足够数据时，只能给出信息收集实验或低风险验证动作，不得编造行业基准。

## 不应做的事

- 不因为用户说“没流量”就建议多发、投广告或换平台。
- 不把播放量、点赞量或粉丝数直接当作有效用户资产。
- 不在没有产品、人群和承接信息时给出精确转化率目标。
- 不同时安排多个平台、多个产品和多个增长实验。
- 不把书中 2020 年前后的平台战术当成今天仍然有效的硬规则；优先提取其底层机制，并标明时效风险。
