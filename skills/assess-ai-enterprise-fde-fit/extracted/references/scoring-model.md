## 1. 总体规则

将1–5题目分映射为0、25、50、75、100；反向题先用`6-原答案`转换。维度分为相关题目的平均分，再应用证据修正。总分为维度分乘权重后求和，四舍五入为整数。

不要为了得到特定结论修改答案。缺失题超过该维度20%时输出区间，并标注需补充的信息。

## 2. AI企服适配度

| 维度 | 权重 | 证据修正 |
|---|---:|---|
| 可验证AI交付能力 | 25% | 是 |
| 行业经验与业务理解 | 20% | 部分 |
| 客户资源与可触达性 | 15% | 是 |
| 咨询表达与销售能力 | 15% | 部分 |
| 产品化与项目管理 | 15% | 是 |
| 时间资金与风险承受 | 10% | 否 |

## 3. FDE适配度

| 维度 | 权重 | 证据修正 |
|---|---:|---|
| 技术实现与系统集成 | 25% | 是 |
| 业务需求翻译 | 20% | 部分 |
| 调试与复杂问题解决 | 15% | 是 |
| 客户现场沟通与协作 | 15% | 部分 |
| 项目交付与结果负责 | 15% | 是 |
| 快速学习、抗压与适应 | 10% | 否 |

## 4. 商业化成熟度

商业化成熟度主要基于事实清单，不以主观意愿替代。

| 维度 | 权重 |
|---|---:|
| 真实案例及使用证据 | 25% |
| 可量化业务结果 | 15% |
| 可重复交付流程 | 15% |
| 明确产品、报价与边界 | 15% |
| 获客入口与有效线索 | 15% |
| 客户证言或信任资产 | 10% |
| 验收、维护与风险机制 | 5% |

事实评分锚点：0=不存在；25=刚开始准备；50=已有雏形；75=已被真实客户验证；100=多次验证、稳定复用或复购。

## 5. 证据等级

| 等级 | 判定 | 修正系数 | 置信贡献 |
|---|---|---:|---:|
| E0 | 只听说过，无实际操作 | 0.55 | 20 |
| E1 | 学习或零散使用 | 0.65 | 35 |
| E2 | 完成个人练习或演示项目 | 0.78 | 55 |
| E3 | 为真实用户完成一次交付 | 0.90 | 75 |
| E4 | 多次交付并有量化结果 | 1.00 | 90 |
| E5 | 标准化产品、复购或规模化交付 | 1.05，上限100 | 100 |

对“证据修正=是”的维度，将原始维度分乘系数。对“部分”维度，只对其中可被事实验证的50%应用系数：`修正分=原始分×(0.5+0.5×系数)`。

证据必须能说明：做了什么、为谁做、是否真实使用、产生什么结果、是否可重复。截图、演示、链接、客户反馈、合同/验收、数据前后对比都可作为证据；注意隐私脱敏。

## 6. 置信度与等级解释

置信度=`回答完整度×40% + 证据置信贡献加权均值×50% + 一致性×10%`。

- 80–100：高置信度
- 60–79：中置信度
- 0–59：低置信度

适配度解释：

- 85–100：高度适配，可优先验证或扩大交付
- 70–84：较适配，补齐关键短板后进入市场
- 55–69：条件适配，宜选择窄场景和小型POC
- 40–54：暂不建议作为主路线，先积累证据
- 0–39：当前不适配，应先补基础条件或选择其他角色

商业化成熟度解释：

- 80–100：可复制增长
- 60–79：可稳定销售
- 40–59：可小范围试卖
- 20–39：需先做样板案例
- 0–19：仍处于学习探索

任何分数都必须附带：依据、反证、下一步最小验证动作。不要用分数替代判断。

## 7. 企业客群匹配

按以下公式独立评分：行业邻近25、问题与方案匹配25、客户可触达20、交付容量20、信任/案例10。

常见客群只作为候选生成器：

| 客群 | 常见要求 | 常见切入口 |
|---|---|---|
| OPC/个人创业者 | 快速、低成本、结果直接 | 内容、获客、个人工作流 |
| 本地门店/小微企业 | 低学习成本、能现场辅导 | 客服、私域、报表、营销 |
| 电商/内容团队 | 高产能、素材复用、数据反馈 | 内容工作流、智能客服、选品分析 |
| 专业服务机构 | 知识密集、准确性与隐私 | 知识库、检索、文档自动化 |
| 传统中小企业/工厂 | 流程理解、系统连接、现场协同 | 报表、知识传承、质检、流程自动化 |
| 软件/互联网公司 | 技术深度、API与产品协同 | AI功能POC、Agent、系统集成 |
| 中大型企业 | 安全合规、采购、治理、复杂协作 | 诊断、培训、受控POC、FDE实施 |

不得仅根据企业预算推荐。先判断用户是否进得去、交得出、收得回款。
