# 生财深度调研教程工作流（scys-deep-tutorial）

把「一个问题/方向 → 生财站内检索 → 深读结构化 → 双导师点评 → 图文 HTML 教程」封装为可重复执行的标准流程。适用于：主题调研教程、人物精华帖教程、航海手册教程、项目案例拆解教程。

## 前置条件

1. **scys-mcp 已配置**：`searchTopic` / `contentSearch` / `topicDetail` / `userSearch` / `activitySearch` / `activityManualToc` / `activityManualDetail` / `projectLibSearch` / `startAiYiRenChat` / `startLiuXiaoPaiChat` 等工具可用。官方玩法提示词库见 scys.com/onepage/mcpHelp。
2. 可选：Chrome（headless 渲染验收）、Pillow（空白段扫描）。不可用时降级为纯静态程序化检查（见 references/acceptance-and-pitfalls.md）。
3. **若 scys-mcp 整体不可用**：明确告知用户，由用户选择「降级为纯世界知识+联网检索版教程（无双导师，显著标注未经站内检索与点评）」或终止。**不得冒充已做站内检索或双导师点评。**

## 输入契约

| 参数 | 必填 | 说明 |
|---|---|---|
| 主题/问题 | ✅ | 一个问题、一个方向、一个人物、一本航海手册或一个项目案例 |
| 素材范围 | 可选 | 指定人物（按昵称）/ 手册（按航海名）/ 关键词 / 时间窗 / 是否仅精华帖 |
| 学习者背景 | 可选 | 学习者的项目与水平，用于教程定制与导师点评适配；含隐私时教程中做匿名化（如「一位独立开发者」） |
| 深读篇数 | 可选 | 默认 8–15 篇全文深读，其余候选做要点级阅读 |
| 输出目录 | 可选 | 默认 `./scys-tutorial-output/YYYY-MM-DD-<主题短slug>/` |
| 是否联网补充 | 可选 | 默认允许，仅限公开网页检索与阅读（不用于获取需授权的站内资源）；补充内容必须标注【补充】 |

交互场景：开工前用一句话向用户复述理解（主题 + 范围 + 预期篇幅）即可执行，不阻塞等确认；自主运行场景（自动化调用）直接按默认参数执行，并在产物「数据说明」中注明所用参数。

## 输出契约（交付判定标准）

```text
<输出目录>/
├── YYYY-MM-DD-<主题>-教程-AI双导师点评版.html   # 终版，唯一交付物，单文件 HTML
├── draft/
│   ├── YYYY-MM-DD-<主题>-教程-初稿v1.html       # 初稿存档（无后缀保留）
│   └── parts/                                   # 分片段构建的片段（保留可复用）
├── notes/
│   ├── 00-候选索引.md                           # 候选池：ID/标题/作者/数据/入选或排除理由
│   ├── 深读笔记-{A,B,...}.md                    # 逐篇：作者/链接/核心数据/方法论/金句原文/可用章节
│   ├── AI亦仁点评-<主题>-YYYY-MM-DD.md          # 点评全文 + 会话ID + 记录ID + 逐条核对备注
│   ├── AI刘小排点评-<主题>-YYYY-MM-DD.md
│   └── 导师会话ID.md
└── assets/                                      # 可选：仅用户确认获取图片时创建
```

**视为完成的充要条件（缺一不可）**：

1. 终版 HTML 通过验收清单（references/acceptance-and-pitfalls.md §1，有渲染条件时加 §2）；
2. 覆盖知识结构七要素（references/tutorial-structure.md §1），收尾含「核心关键 / 难点 / 核心障碍 / 典型误区」四节；
3. **经过双导师点评并逐条修订**，终版附录含 R1-Rn 修订记录；
4. 全部素材可溯源，读不到 / 未覆盖 / 补充的内容如实标注。

## 流程总览（八阶段）

| # | 阶段 | 产出 | 详细协议 |
|---|---|---|---|
| 1 | 需求澄清与检索规划 | 3–6 组检索词 + 素材范围类型 | references/research.md §1 |
| 2 | 站内检索建候选池 | notes/00-候选索引.md | references/research.md §2 |
| 3 | 全文深读（子代理并行） | notes/深读笔记-*.md | references/research.md §3 |
| 4 | 知识结构化（映射七要素） | 章节大纲 | references/tutorial-structure.md §1 |
| 5 | 初稿 HTML（分段构建+静态自检） | draft/初稿v1.html | references/tutorial-structure.md §2 |
| 6 | 双导师点评（并行提交+异步回收） | notes/AI*点评-*.md | references/mentor-review.md §1–§3 |
| 7 | 逐条修订出终版 | 终版 HTML（含 R1-Rn 记录） | references/mentor-review.md §4–§5 |
| 8 | 验收与交付 | 清单全过 + 交付汇报 | references/acceptance-and-pitfalls.md |

并行提示：阶段 3 的多篇深读用子代理并行（每代理负责一批篇目，自包含提示词）；阶段 6 两位导师必须**同批并行**提交。

## 硬性红线（不可跳过）

1. **双导师点评是交付闸门**：初稿 → AI 亦仁 + AI 刘小排并行详细点评 → 逐条修订出终版。未经此流程不得视为完成；导师工具不可用时按「前置条件 3」处理并显著标注。
2. **引用失实必须核对**：双导师点评中涉及「引用 / 事实纠正 / 案例细节」的意见，先回原文或初稿核对再决定采纳——数字分身会误读初稿不存在的对象、注入无信源细节。核对结果逐条备注在点评归档文件（详见 references/mentor-review.md §4）。
3. **默认只读**：点赞 / 投锚 / 收藏是真实写操作（投锚消耗站内资产、每日有上限），执行前必须列清单经用户确认。
4. **默认零外部下载**：不主动发起任何外部网络请求下载资源。站内图片一律用 CSS 原生绘图 + 文字转述卡 + 站内原帖链接呈现；仅当用户明确确认**具体图片清单**后，才通过受控的已授权工具获取；不手工拼接 / 转写 / 复述任何带签名的完整访问 URL 或参数，产物与笔记中只记录来源 ID + 序号；任何获取失败统一降级为文字卡。
5. **如实标注**：读不到的正文（飞书登录墙、手册限已报名船员）、获取失败降级为文字卡的配图、仅要点级阅读的篇目、世界知识或联网补充的内容（标【补充】），一律如实标注，不得编造站内内容或数据。
6. **收入与案例做预期管理**：案例收益数字必须同时给中位数 / 普通参与者对照，并提示幸存者偏差；引用站内原话保留完整原文并附出处链接。
7. **限流纪律**：MCP 约 40 次/分钟，批量检索加间隔；子代理并发触发限制时改串行。

## 快速开始（最小可用路径）

时间紧张或用户只要轻量产出时，允许缩减规模但**不可省略阶段**：候选池 ≥20 篇 → 深读 ≥5 篇 → 初稿 → 双导师点评 → 修订 → 验收。所有缩减在终版「数据说明」节注明。
