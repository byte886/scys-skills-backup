# 阶段 4–5：知识结构化与 HTML 构建

## §1 知识结构七要素（章节大纲映射）

教程大纲必须覆盖以下七要素，缺项要在导读「素材声明」中说明原因：

1. **核心概念讲解**：是什么、为什么。建议用概念表呈现：概念 | 它是什么（事实性知识）| 为什么这样运转（概念性知识）。
2. **概念间逻辑关系**：用流程图 / 关系图呈现（`.flow` 组件或 CSS 原生绘制），让读者看到闭环与飞轮，而不是孤立概念。
3. **事实性 vs 概念性知识分类讲解**：事实 = 可查证的数据 / 规则（会变）；概念 = 运转逻辑（相对稳定）。分开讲，读者才知道哪些需要持续刷新。
4. **程序性知识总结**：方法论框架层——怎么做的一条主线。
5. **实操 SOP**：细到可跟着执行。每步给：动作 / 工具 / 耗时 / 产出物 / 判断标准；必须含量化**止损线**（什么情况放弃、按什么数字判断）。
6. **实战案例**：真实数据 + 复盘，正反案例兼收；每个案例必须带「预期管理」：中位数对照、幸存者偏差提示、执行期与回报期错位。
7. **收尾四节**：核心关键 / 难点 / 核心障碍 / 典型误区（误区建议 ≥10 条，每条给「错误做法 → 正确做法」）。

补充要素：

- 开头「读者状态自检」（时间账 / 能力账 / 预期账：先判断适不适合再往下读）+「素材声明」（来源构成、检索时间窗、局限）。
- 查漏补缺处标注【补充】。
- 若提供了学习者背景：增设「学习者定制」章节，把通用方法论落到其具体情境；双导师意见冲突时并列呈现、标注分歧、交学习者拍板。
- 收尾可加「N 天行动清单」（第 1 天最小行动 → 每阶段里程碑 → 止损检查点）。

## §2 HTML 构建规范

### 版式
- 单文件 HTML、内嵌 CSS、零外部依赖、`lang="zh-CN"`。直接复制骨架 `assets/tutorial-skeleton.html` 改写。
- 结构：`header.hero`（标题 + 一句话定位 + 素材声明 + 标签）→ `.toc` 锚点目录 → 各 `<section id="sN">` → footer。
- 组件词汇表：`section` 章节卡片 / `.card` 内容卡 / `.warnbox`（风险警示）/ `.goldbox`（关键认知）/ `.flow + .step + .arr`（流程图）/ `blockquote(.src)`（引用原文）/ 表格（表头 `th`）/ `.badge` / `.stat`（数据点）。
- 引用站内原话**完整不打折扣**，blockquote 附 `.src` 出处；站内链接格式 `https://scys.com/articleDetail/xq_topic/{entityId}`。

### 图片（默认零外部下载）
- **默认不下载任何外部图片**：站内图片一律用「CSS 原生绘图（表格 / flow / 卡片）+ 文字转述卡 + 站内原帖链接」呈现，产物零外部请求，信息完整性不受影响。
- 仅当用户明确确认要获取的**具体图片清单**后，才通过受控的已授权工具将图片放入 `assets/`（命名 `{短前缀}-{来源ID}-{两位序号}.webp`，HTML 用相对路径引用）；获取后必须 `file` 验格式 + md5 去重（坑见 acceptance-and-pitfalls.md §3）。
- 不手工拼接 / 转写 / 复述带签名的完整访问 URL 或参数，产物与笔记只记来源 ID + 序号；任何获取失败统一降级为 CSS 文字卡并注明，绝不放死链。

### 构建
- 篇幅大（>60KB 或 >8 章）时分片段构建：`draft/parts/part-XX.html` + 拼装脚本（python3 读序拼接或 cat）。片段保留，便于增量修订复用。
- 每个片段标签自闭合完整：不要把一个 `<section>` 拆到两个片段中间；用替换法插内容时极易吞掉锚点携带的闭合标签——改完必须跑开闭标签计数比对。
- 初稿完成 → 跑静态自检（acceptance-and-pitfalls.md §1）→ 再进双导师阶段。

### 附录必备
- 「数据说明」节：检索时间窗、关键词清单、深读篇目与仅要点阅读篇目、未读到处、图片失败记录、所用输入参数。
- 双导师点评版增加「AI 双导师点评与修订记录」章：两位导师核心意见综述 + R1-Rn 逐条修订表（意见来源 / 意见 / 处理状态 / 改动位置 / 核对后不采纳的理由）。
