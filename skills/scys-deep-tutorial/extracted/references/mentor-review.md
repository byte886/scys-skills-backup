# 阶段 6–7：AI 双导师点评协议

双导师 = 生财 MCP 的两个数字分身：**AI 亦仁**（`startAiYiRenChat`，创始人视角：商业判断 / 方向 / 可行性）与 **AI 刘小排**（`startLiuXiaoPaiChat`，AI / 产品 / 增长视角）。点评是交付闸门。

## §1 并行提交

初稿 + 静态自检通过后，**同批并行**调用两个 start 工具（同一消息内两个工具调用）。提问模板（按教程类型增删）：

```text
我写了一份《{主题}》图文教程初稿，请给我详细点评。

【学习者背景】{学习者背景；未提供则写「通用学习者：对{主题}感兴趣的独立从业者」}
【教程大纲】{逐章结构清单，一章一行}
【核心数据与关键结论】{5–10 条}
【关键 SOP 摘要】{可选}

请逐章/逐节评审：1) 结构合理性与遗漏；2) 内容准确性（如有失实请指出并说明依据）；
3) SOP 可执行性（缺哪些判断标准 / 止损线）；4) 案例预期管理是否到位；
5) 典型误区遗漏；6) 对该学习者的适配建议（具体到改哪一章）。
请给逐条意见，并标注每条的严重程度。
```

- 商业判断 / 方向类问题优先找亦仁；AI 工具选型 / 产品 / 增长类优先找刘小排；结构评审两人都做全文级。
- **注意**：给刘小排的提问不要出现「亦仁《某帖名》」这类署名 + 帖名组合——实测会导致后端不生成回答记录（多次轮询为空）。改用「站内某帖 / 社区创始人帖」表述。
- 多轮追问：把返回的 `userAiChatSessionId` 传回同一个 start 工具即可延续会话。

## §2 异步回收

- start 返回的 sessionId + recordId 仅代表**受理**，回答异步生成；用 `queryAiYiRenChat` / `queryLiuXiaoPaiChat` 轮询（首次约等 2 分钟；返回空 = 记录未生成，再等待重试）。
- 同一记录 3 次轮询仍为空：不再等待，**换措辞重新 start 新会话**（配合 §1 的措辞坑）。
- 回答完整后**全文落盘** `notes/AI{亦仁|刘小排}点评-<主题>-YYYY-MM-DD.md`，文件头部记录会话 ID / 记录 ID / 提交与回收时间。

## §3 截断追补（标准动作）

- query 单次输出被截断（回答尾部戛然而止）：先**带 recordId 精确重查**——原始 JSON 的 generateAnswer 段可能含完整文本（展示层截断 ≠ 内容截断，completionToken 可佐证）。
- 仍缺小节：同会话发起「请逐字复述你上一条回答中缺失的『{小节名}』部分」追补提问，拼接后归档。
- 不要把展示截断当作「导师意见不完整」而跳过对应修订。

## §4 引用失实核对（强制）

数字分身的点评可能失实，**凡涉及事实 / 引用 / 案例细节的意见，先回原文或初稿核对，再决定采纳**。已实测五种形态：

1. 批评初稿**不存在**的内容（对大纲摘要的误读，例如批评一条初稿没有的止损线）。
2. 否认自己原帖里的原话（回原帖逐字核对确认后再定）。
3. 修正自己原帖的数字 / 门槛（处理为「双口径并存 + 前提标注」，不直接照改）。
4. 注入无站内信源的案例细节（按「观点参考」处理或丢弃，不写入教程事实层）。
5. 张冠李戴他人观点 / 误读比喻为实指。

处理规则：逐条意见标注「采纳 / 部分采纳 / 核对后不采纳」三态；核对过程与理由写进点评归档文件的「逐条核对备注」；方向性意见即使事实失实也可吸收其方向。

## §5 逐条修订出终版

- 意见清单 → 逐条落实修改，编号 R1、R2…；两位导师意见冲突时**并列呈现、标注分歧**，交学习者拍板；自主场景按「更保守 / 更可逆」取向选择并标注裁定理由。
- 终版文件名加「AI双导师点评版」；附录写「点评综述 + R1-Rn 修订记录」；初稿 v1 无后缀保留在 draft/。
- 仅单导师可用 / 双导师均不可用：教程显著标注「单导师版 / 未经双导师点评」及原因，交付说明中同步声明——不冒充完整流程。
