# 写作与内容核对

## 1. 目标和条件要影响正文

先判断定制版或通用版。定制版说明会员当前阶段、目标、已知条件和假设，可以直接对读者说“你”；未获确认的假设标“未经确认的示例条件”。通用版开头写“本手册按以下读者画像编写”和“条件不同时怎么调”，正文用不带第二人称主语的祈使句，不写“你的条件”“未经你确认”。请求不明且视角会影响路线时先集中问。默认条件只能用于明确委托自行决定或无人值守的示例，不冒充真实情况。

完成正文后反查条件：每个关键条件究竟改变了哪些动作？只在开头写一张表、正文仍照抄来源，不算定制。

## 2. 操作和判断步骤用同一结构

步骤标题写 `## 步骤 1 …` 或三级标题，站内来源才用 S1；旧 `S1` 步骤标题要迁移，文件检查会明确失败。操作和判断步骤都先用一句话写 **目标**，再列 3–5 条编号动作，最后写 **做完的标准**。操作清单交代需要什么、从哪进、填什么、卡住后怎么处理；判断清单交代输入、理由、反例和下一动作，完成标准写可观察的决定。依据在动作后用来源标记定位。一个动作只说一件事；超过约 120 个汉字的段落优先拆成短段或清单，不为满足数字拆断必要的公式、原文引语或代码。

按钮名和路径必须有本次原文、原图或已授权的实际界面依据。站内缺失时，可读取平台官方帮助补步骤。不能用“按常见界面”“进去自己核”掩盖凭空补出的完整路径；知道到哪层就写到哪层，缺口紧跟受影响的动作。

按前置条件核对全部必需动作，包含没有写出的动作。某步完成结果是下一步输入时，要能对上。

## 3. 阅读说明、路线图与来源导航

源稿正文以“阅读说明”开头，紧接按周或阶段的“路线图”，源稿不手写目录；顺序与路线图写法见 [手册组织与步骤](manual-outline.md)。阅读说明集中说明数字若来自作者自述、平台规则可能变化、手册不承诺结果，以及虚构示例的性质。正文不逐段重复这几句；某个动作涉及投入、资格、时效或样例可能被误当真实时，仅就该动作补一句具体限制和核对办法。判断标准是删掉此句会不会改变该动作的安全执行：不会就留在阅读说明，会就就地保留。

正文保留 `[O1]`、`[S1]` 等稳定来源标记，但每个标记要能跳到文末对应来源。一个判断同时由多个来源支持时，合成一个标记组（例如 `[O1、S2]`），不要连写 `[O1][S2]`。文末每条来源有可点的“回到正文”，重复引用时至少回到第一次出现的位置；Markdown、网页和 PDF 均核对双向跳转。定位不等于证实，仍须按下节核原文上下文与证据等级。

**取资料的过程不写进读者正文。** 例如“某网站拒绝程序访问、返回 403，改读网页存档”，读者用不上；读者需要的是规则本身、适用范围和日期（如“2026-09-22 存档版”“2026-10-05 现行页面”）。取得方式、存档链接与快照日期写在来源节对应条目和 `sources.md`，失败与重试写在 `run_notes.md`。阅读说明、正文、附录都属于读者正文，只有来源节例外。

## 4. 素材覆盖与可套用内容

**篇幅：更细更全优先。** 可读性靠结构解决（路线图、章首导读、主线与附录分层、跳转链接），不靠删信息；不设页数或字数上限。调整结构时只删取资料的过程和跨章重复，其余内容移动而不删，做法见 [手册组织与步骤](manual-outline.md) 第二节。

写作前在 `sources.md` 标出每条已读材料的可用案例、反复出现的做法、可直接改写为模板的结构及不可用原因。材料充足时，挑约 6–8 个条件和路径不同的代表性案例；不足时只用实际可用数量，不为凑数引入未经核实内容。每张案例卡写“起点／做法／结果（作者自述）／来源”，缺结果就写未披露，不能推造；相似案例可合并成对照，但不能把 17 人压成 2 人而不说明取舍。

来源已有总结性做法时，逐条判断是否适用并吸收进相应步骤，在 `plan.md` 记录采用、舍弃与理由。至少提供与目标有关的可直接套用模板，例如自我介绍、帖子结构、回复话术；占位值标为虚构或待填写，不冒充会员经历。写完对照主素材有效内容：关键动作、案例、反例、方法和模板若被压没，补回可用部分；正文不应明显短于主素材的有效信息量，但不靠重复、臆造或无关材料凑字数。

## 5. 每条说法保留原来的性质

| 来源或内容 | 怎样写 | 不应升级成什么 |
| --- | --- | --- |
| 现行且适用的官方全文 | 平台规则，附适用范围和生效日期 | 所有地区、账号永久适用 |
| 官方搜索摘要 | 只看到摘要，注明支持哪部分 | 已读全文、全部条件已核 |
| 第三方报道 | 某来源报道，追溯其一手出处 | 平台自己的承诺 |
| 个人帖子、教练经验 | 某人当时怎么做、什么条件、得到什么 | 通用规律、因果结论 |
| 项目库区间 | 平台参考区间，方法和样本未知则写未知 | 普通人的平均成绩、成功率 |
| 助手组装的路线和进度 | 明确为建议，说明输入和理由 | 用户确认、真实经验、结果承诺 |

一份适用的官方原文可以支持规则，不必凑两份；多个独立案例也不能直接推普遍结果。同团队手册互相照抄、报道转述同一材料，不算独立证据。作者不明的手册段落写“该期手册”，不靠截图头像猜作者。

## 6. 数字、日期和计算分开

直接引语保留原文。转述可作等值单位转换，但保留原数与单位，不改变时间范围、收入口径或分母；不得推造原文没有的成绩。

预算、时间、利润演算必须展示输入和公式，假设明确标注；进度和退出条件为助手建议，不作为平台规则或成功预测。

官方规则优先读当前页面；读不到才用网页存档。最新快照也可能是 Cloudflare 验证页，遇到验证页须从存档索引另选可读快照，不把验证页当原文；在来源条目写明实际阅读的快照日期与存档链接，正文据此写“某日存档版”。之后能读到现行页面时，按现行页面复核并更新正文与来源条目，变化写进 `changes.md`。

发布时间、生效时间、查询时间分别记。没写就标未知，不能拿今天查询证明今天仍有效。开通、付费、收款、内容资格等非数字条款也要核。核不了的既进附录，也在受影响动作之前提示；不让用户先投入再发现不适用。

## 7. 图片服务于动作

写作前对 `plan.md` 中每个关键动作判断：需要真实界面截图、原创流程/结构示意、明确虚构的样例预览，还是有依据的纯文字；纯文字须说明足够的理由，不设最低图数。每张使用的真实截图先看原文上下文，再打开核对。图注写图上实际能看到什么、来源、日期及适用边界。旧界面与新规则冲突，要在图旁说明，必要时换图。

没有合用截图时，可据已核实规则画流程/结构图，或用明确虚构的产品样例解释动作；图注必须标“教学示意”，注明依据或虚构来源、制作日期及适用边界。**不得绘制未经核实的平台后台界面**，也不得让示意图承担按钮路径的证据职责。确实不需图时仍可用有依据的文字；不要求固定张数。宽高比只用于提醒复核；横条、表格单行可能是真截图，不为脚本评分删掉它。装饰图不可冒充关键步骤证据。

## 8. 失败、违规和不确定的部分

按 [不采用的做法](forbidden-practices.md) 判断实际行为和上下文，不靠词命中直接下结论。原帖有合用内容但夹着违规步骤，只取能用部分并说明跳过什么、替代办法的依据与局限。不要把站内样本扩成“多数人都靠这种做法”。

查失败复盘、投入差异和样本缺口。没有失败记录不表示没有失败。退款、流水、营收、利润等口径不混用。

## 9. 内容核对与交付结论

文件脚本通过，只证明它检查的文件事项。内容核对至少检查以下几项，并在 `review.json` 保存具体依据；格式见 [记录与复用](records-and-review.md)。

| 检查项 | 怎样核 | 未完成时 |
| --- | --- | --- |
| 目标、路线与个人条件 | 对照用户请求、条件及假设，看正文是否匹配 | 标明待确认或部分完成 |
| 开头与结构 | 源稿以阅读说明开头、紧接路线图，没有手写目录；路线图每步可点到章节，表下写先不做什么、以后再看什么；每章有 2–3 行导读，查阅内容在附录且原位有跳转，同一段意思只出现一次；读者正文没有取资料的过程 | 改结构，不删有效信息；局部更新只改受影响部分 |
| 必需动作与前置条件 | 从目标倒推动作；逐步检查输入、输出、来源及缺口 | 不因少写一步而漏检 |
| 关键规则及引用 | 实际读引文上下文，核适用范围和有效期 | 缺口放在受影响动作之前 |
| 数字与事实性质 | 核出处、口径、公式、经验与推断区别 | 降低结论确定性或删除不支持的说法 |
| 图与所在步骤 | 对照 `plan.md` 逐张打开核内容、清晰度、来源日期与边界；网页检查可放大，PDF 检查图与图注同页 | 0 图提醒人工复核可读性；无依据不编 |
| 时间及安排 | 加总准备、操作、反馈时间，核可用时段 | 删减或分天，不只改条件表 |
| 请求范围与更新 | 局部改动是否保留有效内容、同步所有受影响引用 | 保留旧版和变更说明 |

分别报告文件检查、内容核对、真实试用；不合并成“全部通过”。助手逐步推演不算真实新手试用；局部实机检查不能证明整本已试用。关键动作缺依据时明确“部分完成”。没有真实未知项就写暂无，不凑条数。
