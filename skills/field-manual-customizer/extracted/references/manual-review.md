# 无终端或 Python 时的人工核对

逐项对照 Markdown 源稿、HTML 网页、资料原文及用户请求，把结果和具体依据记录在交付说明或 `review.json`。未做的项目写“未核”，有阻断缺口写“部分完成”；文件检查固定写“未运行”，不能合并说“全部通过”。

| 项目 | 人工检查 |
| --- | --- |
| 目标与条件 | 目标、当前阶段、投入、地区或资格是否与用户已给信息一致；假设是否明确标出 |
| 写作视角 | 一级书名后第三行是否写明“手册类型：定制版/通用版”；定制版的“你”是否只指已知读者；通用版是否写明读者画像与条件变化时的调整方法，步骤是否用客观祈使句 |
| 必需动作 | 从目标倒推逐项列出，核前置条件、实际动作、可观察结果、卡住后的下一步；没写出的动作也要检查 |
| 步骤可读性 | 标题是否用“步骤 1”等编号（S1 留给站内来源）；判断步骤是否把输入、理由、反例、下一动作写进清单；每步是否有一句话目标、3–5 条动作清单、做完的标准；长段是否拆短 |
| 来源定位 | 每个关键步骤能否回到授权可读的原文段落或官方说明；正文标记能否跳到文末对应条目且回到正文，连续来源是否合组；摘要是否被误当全文 |
| 素材覆盖 | 可用案例是否成卡（起点、做法、作者自述结果、来源），代表性是否足够；来源总结是否吸收，是否有明确虚构占位的可套用模板；正文是否遗漏主素材的大块有效内容，是否为压篇幅删掉有效信息（不设页数或字数上限） |
| 阅读说明 | 作者自述数字、规则时效、无结果承诺、虚构样例是否集中在开头；正文是否只保留直接影响动作的具体限制 |
| 开头与路线图 | 源稿是否以阅读说明开头、紧接路线图，没有手写的“目录”一节；路线图每一步能否点到对应章节，表下是否写了这一阶段先不做什么、以后再看什么并链到附录 |
| 主线与附录 | 每章开头是否有 2–3 行说明解决什么、做完是什么样；对照表、规则摘录、模板、案例卡是否在附录且正文原位有跳转；同一段意思是否只在一处保留；调整结构时的删除清单是否只删取资料过程与跨章重复，移动的内容数量是否不变 |
| 取资料的过程 | 阅读说明、正文、附录中是否残留“拒绝程序访问、返回 403、改读存档”这类过程；官方规则是否先读当前页面，用存档时来源条目是否写了快照日期与存档链接 |
| 规则适用 | 规则的地区、账号、发布日期、生效时间及例外是否覆盖这位用户 |
| 图片 | 对照 `plan.md` 的逐动作配图计划；逐张打开核清晰度、用途、来源、日期、适用边界及“教学示意”标识；零基础手把手手册 0 图时人工复核纯文字可读性并记具体理由 |
| 时间与进度 | 加总准备、操作、反馈时间，检查是否落在用户可用时段 |
| 缺口 | 关键未知是否在受影响动作之前写清影响、暂可做什么及怎么补核 |
| 真实试用 | 只按真实操作者、环境、动作和结果报告；助手推演写“未测试” |
| 网页与 PDF | 本地网页核目录、折叠、勾选、搜索、图片放大；PDF 核目录、书签、来源双向锚点、竖长图与图注同页；文件检查不能代替逐图目视核对。手机宽度看第 1 页和正文页的字号、行宽、页边距及表格是否溢出；飞书只上传 PDF 并回读，做不到的逐项标未测 |

人工核对不能替代脚本对文件版本、证据摘要等机械关系的检查；脚本不可用时不要伪造这部分结果。
