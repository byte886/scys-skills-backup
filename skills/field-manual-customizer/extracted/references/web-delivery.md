# 网页交付：从 Markdown 源稿生成离线手册

本地保留 `手册.md` 与 `手册.html`，自动导出成功时以同目录的 `手册.pdf` 为主要交付物；需要放到飞书供手机阅读时只上传 PDF。Markdown 是可修改的源稿，HTML 是生成 PDF 的离线中间产物，仍可在电脑本地打开使用交互功能。复制 `templates/manual.html` 为 `手册.html`，只填模板注释指定的标题、简介、日期、导言、章节和来源区域。沿用模板内嵌的 CSS/JS，不为每本手册重写交互代码，不添加远程字体、样式、脚本或图片；来源链接仅供读者点击导航。

1. 先写好 Markdown，并完成来源、规则、缺口和内容核对。按 Markdown 的顺序将内容转成模板允许的普通 HTML：段落、标题、清单、表格、代码块、行内代码、图片及来源文字。Markdown 在一级书名后第三行写 `> 手册类型：通用版` 或 `> 手册类型：定制版`，开头“阅读说明”“路线图”及读者画像/条件都用二级标题 `##`，供文件检查识别顺序；HTML 的 INTRO 区对应放 `<h2>阅读说明</h2>`、`<h2>…路线图</h2>`，再用 `<h3>` 写条件或读者画像等下级说明（HTML 的视觉层级不改变 Markdown 的二级标题契约）；不要另写“目录”，网页侧栏与 PDF 打印目录由模板按 INTRO 区第一个 `<h2>`、每个章节和来源节自动生成。主线章节与附录章节都用下一步的 `<details>` 结构，附录标题以“附录 A｜”等开头；正文要跳转到的模板、案例卡等条目给稳定锚点（如 `<h3 id="template-t1">`），所有 `#…` 链接都要有目标。模板的 `{{MANUAL_ID}}`（本手册唯一、稳定且不含私人信息）、`{{MANUAL_TITLE}}`、`{{MANUAL_SUBTITLE}}`、`{{UPDATED_ON}}` 和 `INTRO_HTML`、`SECTIONS_HTML`、`SOURCES_HTML` 注释区域是填充位置。不要保留占位符。
2. 每一章按模板的 `<details class="manual-section" id="section-..." open>` 结构填入；`summary` 内放章节标题，正文放在 `.section-body`。章节 ID 唯一且稳定，让目录和章间互引都能跳转。目录及章间链接只用现有的 `#section-...`；清单项的 `data-check-id` 在本手册内唯一且稳定，编辑内容后仍能恢复读者的勾选状态。Markdown 围栏代码改为 `<pre><code>已转义内容</code></pre>`，可选 `class="language-..."` 只标明语言；行内代码用 `<code>已转义内容</code>`。保留原有换行和缩进，不能把字面 ``` 围栏留在网页正文。不认识的语言或未标注语言照常显示，不做语法高亮。
3. 正文的 `[O1]`／`[S1]` 来源标记转为页内链接，指向文末 `id="source-o1"`／`id="source-s1"` 条目；重复引用用唯一 `id="cite-o1-1"`、`cite-o1-2` 等定位。相邻多来源合为一个 `<span class="source-markers">[<a class="source-ref" id="cite-o1-1" href="#source-o1">O1</a>、<a class="source-ref" id="cite-s1-1" href="#source-s1">S1</a>]</span>`，不要连写多个标记。每条来源中放 `<a class="source-backref" href="#cite-o1-1">回到正文</a>`，多次引用至少回首次出现处；来源条目不能只有文字编号。Markdown 源稿也保留同名锚点和双向链接，网页及 PDF 均逐项点击。来源写来源编号、标题、日期、具体定位和核对状态。帖子只用本次 `topicDetail.detailUrl`；项目库和航海材料只用本次 MCP 实际返回的原文链接字段或 [MCP 参考](scys-mcp-tools.md) 已确认的格式。没有地址就保留文字，不拼 ID 猜 URL。外链只接受已核对的 HTTPS 地址，放在 `<a href="..." target="_blank" rel="noopener noreferrer">`，不作为资源加载；PDF 中也检查能点击。不要放带签名的图片 URL 或原始缓存。用户资料按授权用途处理；公开样例只用明确虚构的内容。
4. 所有来源正文和用户文字先做 HTML 文本及属性转义，再放入模板；只保留已核对的必要标签。去掉 `<script>`、内联事件（例如 `onerror`）、`iframe`、表单和可执行 URL。正文图片仅用已核对的 `data:image/png/jpeg/webp` 或当前交付目录下的相对路径，不接受远程地址。每张正文图都写成同一个 `<figure><img ... alt="..."><figcaption>...</figcaption></figure>`，打印样式将竖长图限高 150 mm（A5 高 210 mm，正文上下留 20 mm，图注与边距预留约 40 mm）；竖长图无需手填宽度，但仍须逐图核对图注是否同页，图注写来源、日期和适用边界；原创或虚构图标“教学示意”，不得画未经核实的平台后台界面。案例作者头像只在同一条 `topicDetail` 返回顶层的 `topicUserDTO` 有昵称和头像时使用：将整条原始返回交给 `scripts/embed_avatar.py` 下载并输出内嵌 data URI，最多 200 KiB；在对应引用旁放 `.source-credit` 和以昵称为替代文字的 `<img>`。没有头像、下载失败或网页解码失败就仅显示昵称，不能拿评论者头像充数。不要把原文当成可信 HTML 直接拼入。
5. 自动 PDF 要求网页完全离线且资源都内嵌为 data URL，以便导出脚本只读取这一份 HTML；导出脚本只接受 Skill 随附的固定模板样式与受限 HTML 标签、属性，改写样式或引入新的资源引用会拒绝自动导出。原始网页若有较大或较多的相对图片，可把 `images/` 与 HTML 一起交付，并告知用户使用页面“分享”按钮手动打印，交付说明写“PDF 未自动生成”。压缩图片不能牺牲操作界面文字可读性，来源与用途写在图注。真实头像只允许 PNG/JPEG/WebP；虚构示例中的内嵌 SVG 首字母图是演示占位，不来自 MCP。
6. 本地打开 HTML，检查目录、折叠、清单持久化，以及页面顶部的搜索与导出工具：中文和英文关键词都应列出每处精确子串命中、章节、上下文及高亮词；未跳转前显示“未定位”，跳转后显示当前序号与总数。点结果应先展开折叠章节，再滚动到该处并临时高亮；上下键和上一处、下一处按钮逐处跳转，尚未定位时点“上一处”应跳最后一处，回车跳转当前处（未定位时跳首处），Esc 关闭列表。结果面板在滚动边界不应带动正文；搜索始终不隐藏正文或目录。无结果明确显示 0 处。导出区只有一个“分享”按钮：未自动生成 PDF 时两行原提示和浏览器打印行为保持不变；成功后显示 PDF 文件名和“点「分享」可将 PDF 文件分享给他人”，点击应复制网页所在文件夹路径并弹窗，复制失败时文本框默认选中路径。弹窗的手动打开说明、运行时填入完整 PDF 路径、先复制文件本身而失败时才打开文件夹并选中文件的 AI 提示词、提示词复制成功或失败反馈均需检查；提示词不承诺代发文件。用关闭按钮、Esc 和点遮罩逐项核对弹窗可关闭。检查打印媒体下搜索、导出工具和弹窗全部隐藏，打印专用目录只在打印/PDF 出现，目录项链接到对应章节、无页码；检查打印样式。代码块含长中文提示词或命令时，屏幕与打印均须在块内折行、保留原换行与缩进；正文栏不横向溢出，PDF 核对长行首尾均在且没有文字截断。行内代码应与正文区分。检查所有图片能加载且文字清晰、图与非空图注位于同一个 figure，PDF 中图与图注同页；表格可读、来源与缺口完整；正文图片点击及 Enter/Space 可在当前页放大，放大图沿用原 alt，图片外的暗色区域（含面板空白）、Esc 和关闭按钮均可关闭并把焦点还给原图；点图片本身保持打开，窄屏不超出视口；作者头像不响应放大，打印/PDF 不显示放大层；检查正文来源标记至文末条目及其回链、章间锚点、外链新标签与 `rel`、有头像与无头像的引用，损坏头像应隐藏而昵称保留。用浏览器网络面板确认无外部资源请求，保持模板 CSP 与内联脚本哈希一致。
7. 对完全内嵌资源的网页运行 `python3 scripts/export_pdf.py 手册.html --out-dir <手册输出目录>`。同目录已有同名 PDF 时先保留；同一次运行中为修订本次刚生成的 PDF 而重导出，可用 `--overwrite`，记录原文件属于本次运行；覆盖用户原有 PDF 才须先取得用户同意。脚本先完成 PDF，再只将 PDF 文件名写进网页固定标记；网页不得含本机文件夹绝对路径。导出后按手机宽度检查 PDF 第 1 页和正文页的字号、行宽、页边距、表格换行与溢出；再核对页面背景与打印样式、打印目录无页码且逐项可点、章节级书签（脚本默认向浏览器传 `--generate-pdf-document-outline`，无须额外参数；书签依次为书名、INTRO 区第一个 `<h2>` 即阅读说明、每个 `<details>` 章节和来源节，INTRO 区里的路线图与章内小标题不单列。旧版 Chrome 拒绝该开关时脚本自动退回无书签导出，交付时说明只有可点目录）、来源及章间链接可点、无本机路径页眉页脚，也不出现分享弹窗。自动 PDF 禁用网页脚本，因此网页的损坏头像隐藏兜底不生效；检查 PDF 中头像能否显示。找不到浏览器或导出失败时仍保留 Markdown 与 HTML，注明“PDF 未自动生成”和原因；页面“分享”按钮仍可让读者在 Chrome、Safari 或 Edge 中手动选择“存储为 PDF”，并在打印设置里关闭页眉和页脚。应用内浏览器无法打印时换浏览器。交付说明提醒：手册含其他会员昵称与头像，分享给社区外的人前请留意。飞书只上传 PDF，并回读确认可打开；若 PDF 未生成，明确告知无法完成本次 PDF 交付，不把 HTML 当 PDF 上传。

## 原创教学图：先画源图，再转 PNG

在 `plan.md` 逐个关键动作确认图的用途；无合适截图时，仅依据已核实的流程/结构画教学图，或明确做一个虚构样例，不仿造未知平台后台。把已画好的、只含基本图形与文字的 1200×675 SVG 放在手册 `images/`，例如 `images/路线.svg`；运行 `python3 scripts/render_diagram.py <手册目录>/images/路线.svg --out-dir <手册目录>`。脚本复用本机 Chrome/Edge/Chromium，无须联网安装依赖；只接受纯 SVG、禁止外部资源，输出同目录 `路线.png` 且默认不覆盖。默认 2 倍像素得到 2400×1350 PNG；若在约 8 英寸宽处打印，约为 300 dpi。浏览器不可用或失败时记录原因，不把 SVG 直接放进正文冒充已完成的 PNG。

Markdown 引用 `![图的实际内容](images/路线.png)`；离线单文件网页把该 PNG 转成 `data:image/png;base64,...`，放进同一个 `<figure>` 的 `<img>` 与 `<figcaption>`，用于自动 PDF 时也不读取旁边的 SVG/PNG 文件。图注标“教学示意”，说明依据/虚构来源、制作日期及适用边界；SVG 源和 PNG 一起留在 `images/` 供以后修改和复核。交付前检查小字清晰、网页可放大、PDF 图与图注同页。

模板内联了 mark.js 8.11.1 的压缩发布文件及 MIT 许可证，用于正文定位高亮；命中枚举使用精确子串，避免分词和模糊匹配改变中文结果。生成单本手册时保留该库、许可证、搜索脚本和对应 CSP 哈希，不另行下载或改写交互代码。

无浏览器时可完成 HTML 文件的静态核对，但交付说明要写“交互与打印未实测”。Markdown 内容核对与网页视觉/交互核对分别记录，不能用前者冒充后者。
