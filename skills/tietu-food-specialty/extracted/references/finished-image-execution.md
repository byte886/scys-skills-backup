# 完成图直接交付流程

本文件规定 贴图号·美食特产 如何从题目直接走到可发布的图片。默认交付的是 1—2 张完成图 PNG，不是只给“图片建议”或生图提示词。画图提示词只写入内部执行结构，用于调用与校验；普通用户结果不得返回该字段，更不能用它代替成图。

## 一、先判断图片靠什么成立

先读本次主题、可见素材和正文落点，再选图片类型。赛道只提供偏好，不把图片锁死成固定场景。

- `source_photo`：原图本身就有停留点，如真实物件、食物状态、人物动作、宠物瞬间、作品剧照。
- `source_crop`：原图信息太杂，局部细节比全景更能说明问题；只能裁切，不能补画。
- `documentary_illustration`：没有可用原图，但可以基于已知事实生成普通生活画面示意。它不是现场证据。
- `text_card`：一句观点、提醒或情绪文字才是核心，使用普通底图或干净底板，再由代码写准确中文。
- `comparison_card`：两个状态、前后变化或选择差异需要并排说明。
- `process_sequence`：只有真实步骤至少三个、单张无法讲清时才使用；不能为了“丰富”凑图。

选择顺序：先问“真实原图能不能直接说明”，再问“局部裁切是否更清楚”，最后才考虑生成示意或信息图。不得因为某个赛道过去常用某种图，就把本次主题套回同一版式。

## 二、纯图与叠字分开判断

本赛道配置的兜底值是 `none`。食物外观、切面、手作动作和摊位状态本身就是钩子，默认只出干净实拍图。 兜底值只在主题证据不足时使用，实际仍按本图职责决定。

- `overlayMode=none`：画面本身就是信息。首图 `hasTitle=false`，不得再加标题、黑色遮罩、赛道角标或装饰箭头。
- `overlayMode=title`：没有这一句，读者无法迅速理解情绪或观点。只叠最终标题，中文由代码完成。
- `overlayMode=title_and_annotations`：确实要指出某个局部或差异时使用。标签和箭头必须少而清楚，不能盖住主体。
- 美食、怀旧等实物型主题默认先考虑 `none`；婚姻家庭、女性成长、生活观点等文字落点型主题才优先判断是否需要 `title`。
- 同一赛道不同主题可以走不同模式；同一篇的第二张图通常 `overlayMode=none`。

## 三、真人生活毛边感

“真实”不是固定成“窗边、手拿、桌面”三个元素，也不是故意把每张图做脏。每张图只挑 1—3 个与主题自然相关的不完美：

- 轻微歪斜、裁切不齐、主体边缘偶尔被切到；
- 普通顶灯、阴天光或局部偏亮，允许少量噪点与压缩感；
- 瓷砖缝、旧桌布、塑料袋、皱床单、水渍、泥点、用过的器皿、没有收干净的小杂物；
- 人物姿态不端正、宠物动作没摆好、食物份量不完全一致；
- 场景必须随主题变化：厨房、菜场、楼道、乡间、普通客厅、旧柜子、工作台都只是候选，不是固定模板。

统一负面约束：不要电影感、摄影棚、商业广告、大片构图、夸张景深、虚化光斑、戏剧灯光、完美对称、豪华整洁样板间、精修皮肤、塑料质感、过度锐化、统一复古滤镜、AI 海报装饰。不要在提示词里写焦段、光圈、镜头型号、运镜或“摄像机视角”。

## 四、直接生成完成图

### A. 有可用原图

1. 确认原图由用户提供、已授权或允许使用。
2. `source_photo` 直接使用；`source_crop` 只裁切同一张原图。
3. 纯图模式直接输出 PNG，不叠任何新增文字。
4. 需要标题时，把原图本地路径写入封面输入 JSON 的 `imagePath`，再走代码叠字。

### B. 没有可用原图

1. 在支持内置生图的 Codex 环境，直接调用内置图片生成能力生成无字底图，不再向用户索要生图 API Key。
2. 提示词写具体主体、动作、环境、可见细节和 1—3 处生活痕迹；不得只写“真实、自然、有生活感”。
3. 明确要求不生成中文、标题、标签、箭头文字、数字、字母、Logo 或水印。
4. 生成后先看图：主体是否符合事实，手部/物件是否畸形，是否变成棚拍或电影画面，是否留有虚假标价、人物身份或事件现场。
5. `overlayMode=none` 时，生图结果就是完成图；需要文字时，先取得本地 PNG 路径，再用代码叠加准确中文。

### C. 代码合成与 PNG 输出

封面输入示例：

```json
{
  "title": "正文中的最终标题",
  "imagePath": "/absolute/path/background.png",
  "overlayMode": "none",
  "palette": "使用本赛道已有配色名"
}
```

纯图用 `none`；只叠标题改为 `title`；需要少量标签箭头改为 `title_and_annotations` 并提供 `labels`、`arrows`。运行：

```bash
node scripts/render_finished_image.mjs --input /absolute/path/cover.json --output /absolute/path/finished.png
```

该脚本先调用包内 `render_title_cover.mjs` 合成版式，再转成 1200×1600 PNG。纯图模式必须有真实 `imagePath`，不会用渐变模板假装实拍图。

## 五、交付前验收

- 直接展示或链接最终 PNG；不能只返回提示词。
- 默认 1—2 张，第二张必须增加新信息，不只是换个角度。
- 纯图没有新增标题、黑色蒙层、赛道角标或箭头。
- 叠字图的标题与正文最终标题逐字一致，没有模型生成的乱码中文。
- 有原图时没有换主体、补人物、编地点；AI 示意明确标记 `isHistoricalEvidence=false`。
- 图片主题、正文落点和主情绪一致；没有为了“好看”牺牲事实。
- 用 `view_image` 或等效方式人工看一遍手机竖屏效果，再交付。

## 六、失败必须说清原因

不能生成时返回具体原因和下一步，例如：

- “当前只有文章链接，没有可下载或有权使用的原图，无法执行 source_photo；可改为生活画面示意。”
- “底图工具未返回可保存的本地图片，纯图可以直接交付，但暂时无法进行代码叠字。”
- “图片出现错误人物/食物切面/手部畸形，已判定不可交付，需要重生。”
- “标题过长，代码排版超过五行；请换用候选短标题，不要缩成不可读小字。”

不得把失败伪装成完成，也不要只说“生成失败，请重试”。
